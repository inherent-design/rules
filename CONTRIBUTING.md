# Contributing

Start with the [index](README.md), [development](docs/development.md), and the owning model explanation. Follow the repository's [agent instructions](AGENTS.md) when using an automated contributor.

Make a focused change and exercise the affected boundary. Run the rules check for formal changes, compare generated output with its source, and preserve failing examples. Describe the problem, resulting behavior, actual checks, and remaining evidence limits in the pull request. A native host observation qualifies its recorded profile.

Use conventional commit subjects with proportional explanatory detail. Coordinate commits and pushes with other active owners. Prefer one reviewed integration push over repeated exploratory CI runs. Substantial changes can use dev or a feature branch.

Original contributions use [Apache-2.0](LICENSE). Preserve third-party licenses and attribution. Retained source excerpts need a source identity and their own applicable notices before publication. Keep private fixtures, accounts, downloads, and personal task state outside Git.

Public CI exercises rules and small host fixtures. Application evidence collection follows its own documented local entry point and scope. The [security policy](SECURITY.md) explains how to report sensitive findings.
