# Host and runtime profiles

A profile identifies whose guarantee the caller receives. The same Java class file can reach a different filesystem provider on another host. A worker may be cancelled at the Future layer and still own a native resource. Treat these as separate observations.

### What crosses the application boundary

**Observed** means an executed comparison on the named system. **Documented** identifies an API contract. **Modeled** identifies a checked decision applied to supplied observations. Each cell names the strongest evidence actually obtained for the selected operation.

| Surface | macOS | GNU/Linux | Windows |
| --- | --- | --- | --- |
| File and storage | Observed same-directory replacement and old/new open handles through Python and Java on APFS. | Observed the same on ext4. [rename](https://man7.org/linux/man-pages/man2/rename.2.html) | Documented `ReplaceFileW`, distinct from a content-conditional write. The probe opens both files with explicit delete sharing. [ReplaceFileW](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew) |

These profiles use application-facing APIs. No test invoked a private NT syscall, established a Darwin kernel ABI contract, or inferred physical memory usage from the resource ledger.

## Java baseline and overlays

The macOS builds were Eclipse Adoptium Temurin 17.0.21.1+2, 21.0.13.1+2-LTS, and 25.0.4.1+1-LTS. The Ubuntu OpenJDK binaries reported 17.0.21.1+2-1-24.04.1-Ubuntu, 21.0.13.1+2-1-24.04.1-Ubuntu, and 25.0.5.1+2-1-24.04.1-Ubuntu. Each test compiled with that JDK's javac and ran with its java. Windows uses the same proposed combinations pending an actual run.

| Family | Java 17 baseline | Java 21 overlay | Java 25 overlay |
| --- | --- | --- | --- |
| Files | Open stream, stage, and `Files.move(ATOMIC_MOVE)` on one filesystem. The tested providers replaced the target. The API leaves handling of an existing target implementation-specific for an atomic move. | Baseline recompiled and observed. | Baseline recompiled and observed. |

The [Minecraft 26.3 decoding witness](../host/minecraft/LATER-DECODING.md) is a separate Java 25 consumer profile: forty selected original methods/codecs on the pinned Temurin 25/macOS arm64 environment, with explicit Java-only library identities. Its reflection/linkage outcomes and bounded decoded-state comparisons do not extend Linux/Windows execution, native graphics libraries or provider compatibility. Heap and active-processor settings constrain that process configuration; they are not physical-memory measurements or a host-wide concurrency limit.

The [Bedrock definition lane](../host/minecraft/bedrock/README.md) currently has source profiles only. Keep sample-source commit, schema label, minimum-engine declaration, pipeline/backend and actual executable identities separate. A `beta` declaration, default annotation or documentation example is not an observed host capability or applied value. These source records do not qualify a Bedrock installation on any operating system, or establish equivalence with the Java resource/runtime contracts.

The [1.21.11 consumer lane](../host/minecraft/JAVA-1.21.11.md) separately executes original deserializers and a controlled CPU bake boundary on the pinned Temurin 21/macOS arm64 profile. Its Java 25 Class-File scanner only reads the older client's data. Direct GLFW/OpenGL references in that client and SDL/Vulkan/RenderPearl references in 26.3 require their own versioned window/input/device contracts; neither source census or method fixture loads or qualifies those native backends.

Mobile or embedded adapters can reuse the same trace version while advertising narrower lifecycle, foreground, storage, and device capabilities. Record suspension, unavailable APIs, emulation, and loss of observation as explicit states. Qualification starts with a named runtime and an actual consumer.
