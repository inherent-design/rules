# Cross-application findings and design direction

The studies support simplifying boundaries between values, state, and evidence. They do not support replacing these programs with one package, document, or task model. Preserve each program's purpose and established policies; share host mechanisms only where their premises match.

The [VS Code filesystem band](vscode/FILESYSTEMS.md) adds a concrete distinction between historical event payload and current membership: removal retains a provider object, so forwarding that object's capabilities without the removal flag leaves stale knowledge. New reads correctly fail while a previously captured write can still complete against its old provider. Report membership, admitted work, and actual effects separately. Also retain caller-owned byte snapshots when later dispatch must use an exact image; the observed write shortcut borrows its array. These are application/source observations and a narrow invalidation candidate, not new shared host guarantees.

The [empack world-group band](empack/WORLDS.md) adds history with an ongoing policy effect: initialized roots prevent reseeding even after their world disappears and an intermediate release omits them. An `initialized_worlds` entry is neither proof that the world still exists nor a content-digest reference to its original publisher bytes. Other release/history retention obligations remain separate. Removing initialization because current membership is empty would change authorization. Preserve the group-level rule before ordinary file repair; retain compact preservation reasons for reporting without traversing player data.

The [archive band](empack/ARCHIVES.md) supports retaining separate raw-directory admission, name decoding, namespace validation, selected payload verification, and host publication. A successful earlier check supplies no later grant. Opaque JAR resources and portable destination names legitimately have different lexical rules. The selected CP437/UTF-8 alias is rejected after decoding despite distinct raw bytes. Preserve those stages in a shared parser, and add diagnostic entry context through existing error chains without skipping failed-read accounting. A generated-output verifier's limits are not automatically an untrusted-input memory policy.

This is a partial synthesis of the study through the evidence bands linked below; its initial synthesis used repository revision `f570f2ec68de818ee4c4e1fe700f0675e0d239e8`. The [inventory](inventory.json) remains the current coverage index, and [joined scenarios](scenarios.json) retain their larger obligations. Most operations remain pending, and no entire feature family is qualified. A proposed improvement below is not a production implementation decision.

## Distinctions that must survive simplification

**Identity has a role.** The JavaScript peer fixtures use identical plugin content in different effective contexts. Cargo builds different units with the same lock. Prism's filter can match content at different destinations. Browser handle names can collide across entry kinds or provider lifetimes. Restic's historical parent and retaining tree have different roles despite using digest-shaped IDs. Using those values interchangeably would erase useful information.

**Declared, selected, and effective state differ.** All three JavaScript tools can remove a direct leaf declaration while a parent still loads that leaf. MO2 installed mods and profile activation are separate from the winning effective file. Empack's authoring, exact selection, release, installed baseline, local choices, and runtime ownership need their own state owners. Inspection should explain those relationships instead of treating an absent declaration or root lookup as proof that content is unused. npm also normalizes an absolute local archive reference to a relative spelling during identical re-adoption; serialized spelling and target identity are separate.

**Compaction can change selection.** npm's measured dedupe re-resolves duplicated package names: it can obtain a new compatible version while an exact sibling requirement keeps two copies necessary. Yarn chooses among saved locators, and pnpm's tested seeded profiles reuse an existing compatible selection. Their accurate previews and distinct status contracts should survive reporting changes. Preserve author constraints, selected locators, placements, and cache bytes as different values. [Native controls, source policies, and candidates](js-dedupe/README.md).

**A desired-state index is not an observed installation.** Resolution-only updates in all three JavaScript tools leave an older package runnable while their root locks select the newer archive. In npm's measured profile, the hidden install index also advances; a later ordinary install reports success while retaining the old payload. Removing that private index lets a fresh install reconcile correctly, and a clean frozen install also corrects it. Preserve selected, cached-claim, and observed identities across optimization boundaries. [Native reproduction, controls, and limits](js-peers/LOCK-MODES.md).

**Incoming evidence and saved evidence can need different checks.** Empack's selected channel APIs correctly permit a newer signed offer, but reusing that admission for a stored envelope also accepts an inconsistent older stored floor. Exact saved-pair validation is a narrower proposed caller obligation, not a change to cryptography or monotone offer advancement. This finding comes from independent in-memory source checks, not a reproduced normal update or crash. [Source/model scope](empack/CHANNELS.md).

**Saving an assignment and changing the effective value are different actions.** npm, pnpm, and Yarn use different default write scopes. A higher file or environment source can mask a successful edit. Yarn's measured set headline describes the effective override as what it wrote, and its custom-basename home writer and reader disagree. Preserve target, requested assignment, source, and result separately. [Configuration evidence and alternatives](js-config/README.md).

**An event clock is not a saved image.** Native VS Code undo returns to a clean save point while its document version increases. Empack's proposed edit epoch rejects stale work, while saved-image identity answers whether the current draft is saved. Returning to the same image does not authorize an old attempt's background result. The file/provider incarnation and admitted storage revision remain separate.

**Creating an artifact is not qualifying it.** Cargo retains a local archive after a deliberately failed build check and permits packaging with verification skipped. Its transformed distribution manifest and original author manifest have different roles. Consumers need the actual checked outcome and exact artifact identity before delivery; an expected pathname alone cannot supply either.

**Metadata trust is a policy, not a content identity.** Restic's explicit ignore-metadata options can reuse old content while saving current metadata. Forced rereading can add no new data because deduplication already knows those bytes. Preserve the requested evidence policy and distinguish reads, stored data, captured content, and publication. This local backup policy does not establish suitable validation for empack publisher inputs. [Capture observations](restic/BACKUP.md).

**Completion is scoped to an effect.** Restic forget removes a reference before prune reclaims data. Cargo clean removes its target artifacts while an external script effect remains. MO2 dirty notifications can contain duplicate indices with no net edit. Prism can accept an abort before its base task finishes. A restored browser tab, in-memory handle, finalizer call, and confirmed stored project are different outcomes. Reports should name the affected resource and confirmed or unknown result.

**Query value, protocol, coverage, and status can disagree.** Restic's selected root-tree failure makes pattern search return status 0 with human diagnostics before its JSON array. A failing listing still exposes a useful snapshot header. Preserve partial facts and incomplete traversal separately; do not normalize either into an ordinary empty result. A metadata-only query can succeed while payload reading fails. [Query evidence and proposed completion](restic/INSPECTION.md).

**A target label is not an ordering or compatibility proof.** The [update-selection band](js-updates/README.md) moves a registry's `latest` tag backward while retaining the newer release. npm's explicit tag install and Yarn's classic upgrade follow it; pnpm's latest-update policy retains the higher permitted version. The tools also differ in declaration writing and the meaning of `wanted`. Preserve request policy, tag direction, admitted constraints, observation basis, saved selection, and actual installation separately. Satisfying a direct range does not qualify the rest of a dependency graph.

**Cleanup must agree with saved ownership.** Cargo's binary-install study preserves successful replacement of existing binaries after another replacement fails. A different mixed new/replacement case saves registration for a new binary, then unwinding removes that binary. Registration, surviving content, cleanup responsibility, and overall command failure need separate evidence. A truthful partial result is useful; a saved claim contradicted by later cleanup needs correction at that boundary. [Pinned Cargo observations and candidate policy](cargo-install/README.md).

**A credential change needs an exact target.** Restic changes one password wrapper around an existing repository master key. Another wrapper can still accept the old password, and the current key is chosen for each process. Preserve old/new key identities and confirmed effects instead of reporting an account-wide or cryptographic rotation. Publisher signing keys, repository access wrappers, and service credentials require their own trust models. [Key-custody observations and reporting proposal](restic/KEYS.md).

**The same verb can request a different operation.** Npm's default `exec` can interpret a name as package intent even when an inherited program has that name. Pnpm's default resolves a program and argument vector, while Yarn executes portable shellcode; npm also offers explicit shell calls. Named package scripts are separate again. Preserve the request namespace, acquisition policy, selected target, actual directory, and failure phase rather than unifying command spelling or numeric status. [Execution evidence and per-program decisions](js-exec/README.md).

**Permission and execution have scope.** The JavaScript hook study distinguishes dependency review, root hooks, explicit script requests, and command status. The three tools differ legitimately; a disabled default can still allow a particular explicit or workspace action. A failed command can retain selected files and hook-written output. A shared report should preserve those facts rather than impose one universal script switch.

**Evidence demand follows the operation.** Empack can preserve an existing seed without claiming its bytes match the publisher, while the publisher's bundled seed source still requires verified bytes. Cargo's freshness decision covers declared invalidation inputs, not arbitrary script reads. Browser API presence supplies neither permission nor a successful write. These findings support explicit required observations, capability admission, retained inputs, and completion evidence, not a broad “skip verification” switch.

**Retention follows typed ownership relations.** Restic's `Parent` is not a retaining root. A prepared export or editable undo state may need to retain assets deliberately. A dependency can remain reachable without a direct declaration. Neither following every relation nor ignoring every historical relation is a safe universal collection rule. Complete retaining roots and publication/reclamation coordination remain host premises.

**A retry needs progress or a changed basis.** Prism's obsolete-component loop can propose the same removal after a real permission refusal and ignore the false removal result. Its bounded source-prefix comparison leaves the file and candidate present until a fixture guard stops the test. Report failure and retained state instead of treating another identical pass as progress. This is a source-level caller result problem; a full native GUI hang was not tested. [Failure and codec controls](prism/COMPONENTS.md).

**Remote acceptance and command success are different facts.** The [publication fixture](js-peers/PUBLICATION.md) produces the same transport failure with or without a server-side version, and later hook failures after acknowledged acceptance in all three JavaScript tools. Keep target identity, request outcome, acknowledgement, and later work separate. Dry-run scopes also differ from global nonmutation: selected hooks run, and npm makes registry reads.

## Application-specific decisions

### npm

The [update-selection band](js-updates/README.md) supports preserving range-respecting `update` separately from explicit version/tag installation. Its current/wanted/latest distinction is useful, but a selected 404 can produce an empty status-0 report, and a backward-moving tag can still produce an outdated row. An additive explanation should name unavailable inspection and target direction without changing existing JSON/status semantics silently. Keep the resolver and reification boundaries; a new report must not claim complete graph compatibility or successful fresh lookup from an empty result.

The [configuration band](js-config/README.md) supports retaining the user default write target and existing per-file provenance list. Global-mode reads still include the user layer, so label the effective scope accurately rather than promising a raw global-file read.

Preserve Arborist's distinction between edge validity, placement, and the provider a module actually resolves. The observed shared plugin uses API 1 for both consumers even though the right workspace directly supplies API 2. That valid binding should not be relabeled a failed installation merely because another package manager creates distinct contexts.

A candidate inspection result should connect the direct declaration, requiring instance, actual provider, and retained reason. Removal could explain that a declaration disappeared while a parent still needs the package. Keep npm's observed missing-root no-op policy and successful identical re-adoption. Reuse `ls`/`explain` and existing reification data before inventing another graph or command.

Prefer additive reports that preserve established status and manifest/lock meaning. The keep-current alternative is extra graph inspection by callers. Falsify the candidate with hoisting, optional/peer edges, aliases, workspaces, partial reification, and incomplete evidence; do not infer cache deletion from root lookup. [Detailed basis and checks](js-peers/REMOVAL.md).

The later [lock-mode band](js-peers/LOCK-MODES.md) identifies an implementation correction beyond reporting: lock-only reification publishes a desired hidden index without materializing its payload, and an ordinary install can then trust that index and retain the older exact version. Preserve or invalidate actual metadata until it has an observed basis. Keep the current lock format and flags, but test this sequence before claiming a metadata-only fix is sufficient. The tested `ci` workaround is a clean installation with its own effects, not a harmless inspection command.

The [publication band](js-peers/PUBLICATION.md) supports retaining acknowledged publication across a later hook error and naming uncertainty after a lost response. Reuse the known artifact/reporter data; do not infer absence or retry safety from the generic network failure. Preserve current status/hook semantics and review JSON stream compatibility before changing its envelope.

The [cache band](npm-cache/README.md) adds a scope distinction: successful cache cleanup can remove corrupt backing and leave a requested package unavailable, while installed files remain unchanged. A later offline clean install can clear the old installation before acquisition fails, without changing author/lock bytes. Preserve the clean rebuild policy and the useful cleanup counts; expose installation effects and requested-content availability separately. This is a bounded expected failure path, not a corruption defect. An availability-first alternative needs retained input through clearing, not a global cache-verification Boolean.

### pnpm

The [deployment band](pnpm-deploy/README.md) adds actual copied-runtime closure and a protected-target defect. Ordinary deployments preserve a transitive leaf without making it root-resolvable; source-addressed manifest strings need not be live runtime backing. On the observed case-insensitive Mac, a forced source-directory case alias bypasses lexical admission, removes original program/author files, and exits successfully. Protect actual filesystem resources before destructive preparation, and retain payload/source effects independently of exit status. The proposed physical-conflict guard is not an implemented fix.

The [update-selection band](js-updates/README.md) supports preserving default range refreshes and exact pins while exposing when pnpm advances a written range lower bound. Its latest rewrite retains exact-versus-range style and can keep a higher permitted version than the current tag. Keep the existing selection/version/save options rather than replacing them with a generic “latest” Boolean at reporting boundaries. Inspection's `wanted` is the saved current version in this source; review existing compatible-target inspection before adding an optional, explicitly named constrained-target field. A prior catalog returned after a selected 404 should remain attributable prior evidence, not a new successful lookup. Exact cache-read and cold-cache behavior remain unqualified.

The [patch lifecycle](js-patches/README.md) adds a concrete restoration defect: after an invalid patch changed the live target, restoring the exact valid patch can return success with the old good lock but unpatched runtime bytes. A fresh project reproduces it; forced installation repairs that fixture. Preserve current-state uncertainty after failure and require a valid selected backing before reuse. The conservative private-candidate alternative is modeled, while the complete materializer cause and an efficient production fix remain open.

The [configuration band](js-config/README.md) distinguishes global default writes from project-effective reads and key-specific INI/YAML destinations. Keep the current typed setting and routing rules. A per-key origin view needs attributable collector evidence; merged values alone cannot supply it.

Preserve peer-context identity and the distinction between root visibility and retained reachability. In the fixture, the leaf stops being root-resolvable after direct removal while its parent still loads it. A root-level module lookup is therefore insufficient for either retention or absence claims.

A useful diagnostic can distinguish “not directly declared” from “not present” and identify requiring roots when the graph is known. Keep missing-root refusal and policy checks; do not force-remove transitives or reclaim store content to make the output look successful. The existing `PeerSet` distinction between declared and taken peers should survive any internal cleanup.

An additive result need not change lock/store formats. Keeping current commands plus explicit graph inspection is reasonable. Verify workspace filters, shared consumers, optional peers, incomplete metadata, and store ownership before generalizing; none was established by this local node-modules fixture. [Peer context](js-peers/README.md), [declaration edits](js-peers/REMOVAL.md).

The [lock-mode comparison](js-peers/LOCK-MODES.md) supports preserving pnpm's explicit stale-specifier cause and its lock-only-then-frozen recovery guidance. A successful supply-chain policy check concerns the lock's evidence, while installed payload freshness remains separate. Clarify that distinction through an optional completed-effect summary; a new lock/store schema or another installer is unnecessary for that reporting candidate.

pnpm’s [single-publication path](js-peers/PUBLICATION.md) already has an internal published-summary error record, but drops it when rendering a later hook failure. Preserve that existing fact across the caller boundary rather than inventing another publication model. Ordinary registry conflicts, pnpr release confirmation, and availability polling have different evidence obligations.

### Yarn Berry

The [update-selection band](js-updates/README.md) supports keeping classic `up` and recursive `up -R` distinct: they intentionally differ in declaration changes and the handling of exact pins. A wildcard can also request conversion of a local source into a registry dependency. The retained refusal is a collector scope mistake, not a product defect; preserve deliberate conversion capability. A candidate upgrade summary can show before/after source and range styles through the existing interaction and resolver paths. Keep refusal before selected project publication, without claiming no cache effects or rollback after arbitrary materialization failures.

The [patch comparison](js-patches/README.md) preserves saved recipe versus installed content. Direct saved patches rewrite the workspace dependency in this profile, while transitive source handling can use resolutions; clarify that distinction and the required install step in help/reporting. Mandatory hunk failure preserved the previous patched runtime here. Keep that bounded observation separate from general rollback, PnP, nested patches, and optional-patch policy.

The [configuration band](js-config/README.md) supports a focused set-result correction using the requested stored value and existing effective/source facts. Its custom-basename home read/write mismatch also needs a deliberate compatible target policy. Preserve environment precedence and current explicit JSON provenance; do not silently combine old conflicting home files.

Preserve descriptors, resolved packages, virtual peer contexts, and materialization as different values. Same archive contents do not remove the need for context-specific identity. Immutable installation refuses a changed lock basis; it does not roll back the author's edited manifest or prove no incidental cache effect.

Explore a context explanation that connects the requiring descriptor, effective peer provider, selected linker, and direct declaration. Keep workspace-scoped removal/refusal and identical re-adoption. Review existing peer explanations and project structures before adding API surface. Do not transfer node-modules observations to PnP.

Keep serialized locators and immutable-mode semantics stable. The keep-current alternative is the existing inspection workflow. Qualification must cover PnP, patches, workspace selectors, virtual-package round trips, and immutable failure/partial effects. [Detailed findings](js-peers/README.md), [removal comparison](js-peers/REMOVAL.md).

Yarn's [lock-only flow](js-peers/LOCK-MODES.md) already names the skipped link step. Preserve that phase distinction and keep immutable-lock and immutable-cache policies separate. A final selection-versus-installation summary can build on the existing reporter; the node-modules observations do not qualify PnP or general cache admission.

Workspace runs add selected membership, scripts present, dependency readiness, dispatch, and completion as separate facts. npm continues its workspace loop after B fails; pnpm no-bail permits independent C while blocking A that needs B; the tested Yarn serial topological loop stops. Root inclusion and missing-script policy differ. Preserve those policies and make completed, blocked, and undispatched outcomes visible through existing reporter mechanisms before inventing another scheduler. [Native scope and terminal-results candidate](js-scripts/WORKSPACES.md).

Yarn’s [publication stream](js-peers/PUBLICATION.md) already retains a `published: true` event before a failing postpack hook. Preserve that distinction and connect it to the final failure headline. Keep postpack finalization semantics; a lost response remains unconfirmed publication rather than proof that nothing was accepted.

The [Modern project-constraints band](yarn-constraints/README.md) separately demonstrates capped `--fix` success followed by a failed check, repeated stable evaluations, partial safe edits after conflict/throw, and reference-identity conflicts between equal-looking object values. Preserve saved effects independently of status, and distinguish applied edits from a verified postcondition. Final validation, early termination under stationary inputs, semantic manifest values, and typed issues are candidates; they have distinct compatibility costs. Six `--json` checks also combine human guidance with JSON records. Format guidance explicitly rather than asking automation to parse that mixed stream.

### Cargo

The [freshness/environment band](cargo/FRESHNESS.md) adds a concrete invalidation rule: a dirty unit loses reuse eligibility before work runs, even when its old executable still exists. Cached build-script JSON is output availability, not a process-start witness. A producer can remain fresh while a required generated input is absent downstream; neither a valid producer marker nor an old runnable binary proves the requested build completed. Keep those identities and effects separate in new operation/event interfaces.

Preserve `PackageId`, resolved graph, activated features, compiler `Unit`, and freshness evidence separately. The native app changes compiled features while its lock stays identical. An undeclared external build-script input can change while Cargo still reuses the previous artifact. This is evidence about the declared watch set, not a demand that Cargo infer every arbitrary file read.

For internal consumers, carry the selected unit/request and declared input basis. For operators, a candidate cleanup receipt can name the target root and confirmed scope without promising to undo external script effects. Existing JSON and cleanup APIs need review before choosing a new flag or schema.

Keep existing metadata IDs and package/lock formats. The current approach plus accurate input-declaration guidance is a credible alternative. Verify resolver/profile/target differences, failed scripts, undeclared effects, and cross-compilation before broad artifact claims. A target build or check is not target execution. [Model, native flow, and limits](cargo/README.md).

Local source packaging adds another boundary: Cargo can leave an archive after failed verification, and unchecked creation does not establish compilability. A candidate failure report can identify the retained archive and its failed check while preserving the current exit status. Keep the existing flags and source/normalized-manifest distinction; inspect existing package output before adding an API. Registry acceptance remains separate and untested. [Packaging evidence and verification plan](cargo/PACKAGING.md).

Cargo workspace metadata adds effective-manifest context to the inspection basis: root defaults can differ from member defaults without source changes. CLI exclusion removes selected roots, while a still-required dependency can remain in the compiler-reported check set. Preserve those relations and improve caller scope/provenance before proposing another metadata service. This contrasts with workspace script selection rather than establishing a universal meaning of “excluded.” [Cargo context and dependency evidence](cargo/WORKSPACES.md).

The [feature-context band](cargo/FEATURES.md) adds an important policy distinction: root no-default flags do not cancel another dependency declaration’s positive defaults. Forwarded requests can reach both normal and build uses, even when resolver 2/3 keeps their declaration features separate. Preserve the command and role context instead of describing every resolved feature as compiled. Workspace-wide all-features and conditional-only filtering still need their own evidence. Cargo’s positive feature contributions are not a substitute for empack’s pins, negative constraints, or file ownership rules.

### restic

The [backup band](restic/BACKUP.md) supports preserving partial snapshot evidence after source errors, explicit reuse policy, and dry-run/unchanged distinctions. Existing status, stderr, and summary facts should remain linked; a returned snapshot ID in dry-run is a simulated result, not saved-reference evidence. Reread/new-data counters need their actual scopes. No backup product defect or policy change is selected.

The [integrity band](restic/INTEGRITY.md) supports preserving metadata-only, subset, and full-data checks as distinct operations. A same-size data fault can pass metadata checks, and a successful index rebuild can leave file data unreadable. Candidate reports should name their checked set and repaired namespace. The keep-current option remains sound; no exit-code, repository-format, or automatic destructive-repair change is selected. Post-repair full reads and exact known-file comparison stay separate acceptance evidence.

Preserve reference removal, reachable data, physical packs, and restore as distinct operations. The local run removes snapshot A, leaves pack bytes unchanged, and later prunes A-only data while retaining snapshot B's shared/new data. B's historical parent relation does not retain A's content.

Candidate snapshot/tree/blob/pack ID wrappers can protect high-risk internal boundaries without changing digest bytes on disk. This is a typing opportunity, not a reproduced namespace bug. An optional explicit-ID deletion receipt could distinguish preview, confirmed reference removal, unknown backend acceptance, and requested pruning; the tested explicit-ID JSON commands were silent.

Do not rewrite backup repositories for an internal wrapper. Keep file-type-scoped APIs and post-command inspection if new reports add more complexity than value. Validate remote/partial outcomes, retention grouping, incomplete roots, lock conflicts, and restore after collection; the selected three-blob projection cannot supply those proofs. [Detailed proposal](restic/README.md).

Scope is also part of selection. In the private fixture, empty grouping still leaves `snapshots --latest 1` selecting per host/path, while `forget --keep-last 1` with empty grouping previews one global survivor. `snapshots latest` selects one newest snapshot. Preserve those command-specific contracts and the protective default retention groups; explain effective scope before adding flags or changing defaults. Keep-tag is a union condition, and a preview remains distinct from deletion. [Source/native comparison and compatibility plan](restic/SELECTION.md).

The lock band adds operation-specific coordination: compatible appenders can coexist, but check is exclusive. A retired process can leave a blocking record;normal stale cleanup and actual integrity remain separate. A published candidate is weaker evidence than admitted ownership. Unix SIGHUP probe failures also motivate a source-derived non-intrusive absent/unknown classification candidate,without claiming a reproduced permission/PID-reuse incident. Preserve existing cleanup and status policy; qualify the probe and reporting changes separately. [Lock evidence, privacy, and verification](restic/LOCKS.md).

The [restore band](restic/RESTORE.md) shows why a successful `--verify` request need not check files skipped by overwrite policy or matching size/mtime. Keep those documented tradeoffs, but identify skipped scope and distinguish file content from directory/metadata progress. Selected unexpected-directory deletion also removes an individually excluded descendant; upstream tests explicitly allow that subtree policy. A leaf-aware alternative needs a compatibility decision, existing filter reuse, and partial-effect checks rather than an assumed bug fix.

The [copy band](restic/COPY.md) distinguishes current encrypted snapshot IDs, persistent Original provenance, compared metadata, source content, and destination publication. Tagged variants can coexist; a matching origin alone does not justify skipping one. Copies clear lineage while preserving persistent origin. This supports role-specific identifiers and an explicit copy result, not treating every provenance edge as a retaining root or an authentication statement.

The [input-policy band](restic/INPUTS.md) preserves explicit roots, admitted sources, visited descendants, exclusions, and saved entries as separate facts. Ordered negation cannot restore an unvisited child, and nonzero status can accompany a saved partial snapshot. Keep these documented policies; an improved report should expose the existing distinctions and snapshot ID rather than infer “nothing saved” or introduce a universal exclude-wins rule.

The [comparison band](restic/INSPECTION.md) supports a focused search-completion correction: keep diagnostics on stderr, retain a valid partial array, and fail when traversal is incomplete. Its type-change case also separates a legitimate single `T` event from incomplete blob-difference counters.
