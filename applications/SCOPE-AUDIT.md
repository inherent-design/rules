# Application study: remaining scope and evidence gaps

The nine-application study remains incomplete. Its strongest result so far is a set of attributable component decisions and counterexamples, with a bounded shared-engine portable-authoring join. The next work must connect missing application policies and workflows, and reconcile the target designs. More proof counts or repeated happy paths would not establish that result.

This is an interim review of the selected intent against the canonical [inventory](inventory.json), [scenarios](scenarios.json), [comparison](COMPARISON.md), and their linked reports. The inspected application baseline is commit `b8125d85f8f28f44ded02a5c7e2f6b4f3afe8ee3`, on 2026-11-25 local time. The reference counts below include this review’s reconciliation. It is not fresh verification of every implementation, upstream version, or native capture. Eighteen existing selection-source cache hashes were checked, and selected assessment/migration boundaries were read; no new application, comparator source-fragment, or retained engine-test execution accompanies this review. The reference checker and its rejection controls ran separately. Existing operation and scenario statuses remain unchanged.

## What the current records establish

Of the families, 127 have operation-linked evidence; another has related component evidence without an operation slice. These are reference counts, not completion counts. Pending operations can have useful partial evidence, and unlinked operations can have relevant material elsewhere.

Neither native-observed nor a passing formal model establishes all inputs, hosts, consumers, or joined behavior. ## Reference reconciliation and decision coverage

Nine missing source references now point assessment and migration operations to the existing [selection-policy map](empack/SELECTION.md). The references name inspected scope, classification, option composition, and caller boundaries. They do not turn read test bodies into executed tests, prove retained-pin validity on a new runtime, or qualify a migration publication. Adoption remains a separate observed-content operation; root re-promotion and native state association are not substitutes.

The canonical per-application decision indexes now include previously recorded proposals for all nine applications. There are 34 candidate records, 11 preservation records, and 10 unresolved-choice records. These are references to the comparison and scoped reports, not 55 adopted or verified design changes. The checker validates their IDs, required rationale/status/question, and existing document references. It cannot establish that the proposed change is correct or current upstream.

The reconciliation recovers structural work that a report-only review could overlook: npm hidden-index materialization, pnpm protected deployment and patch backing, Yarn version-decision retention and constraints postconditions, MO2 replacement backing/profile context, Prism destination identity, Cargo install tracking/runner provenance, restic incomplete inspection, and VS Code provider/handle identity. Empack's coherent portable model, initializer publication, and saved-offer validation have separate roles. Keep the detailed premises and alternatives in their owning reports rather than invent another proposal implementation from the index.

Several packages still lack a complete proposal across current types, affected callers, serialized compatibility, host ownership, implementation sequence, and falsifying checks. The comparison is a partial synthesis. Index presence does not resolve those obligations or justify a production change.

The initial inventory is a research decomposition, not proof that each command exists with that spelling in every pinned release. Native help, selected sources, and plugin/version profiles must admit a feature before its behavior is claimed. Preserve unsupported or unavailable profiles explicitly; do not infer them from a blank evidence field.

## Reuse the joins already established

The [portable-authoring join](empack/PORTABLE-JOINED.md) already exercises a shared research engine through import, invalid and valid save/reopen, metadata/path edits, captured-image Prism export, and finalized browser downloads. It is not necessary to build another demonstration of that same sequence. Production project encoding, more providers and recipes, custody of signing material, storage limits, concurrent writers, crash behavior, and actual consumer launch remain separate obligations.

Earlier component reports describe what their own run did not establish. A later component can fill part of that gap without changing an earlier receipt or making its original observation broader. Current summaries should link the later evidence instead of presenting the earlier limitation as a newly missing experiment. Frozen producers, failures, and raw records remain unchanged.

Reuse later joins before treating earlier limitations as new missing experiments:

- **empack:** [author-to-snapshot](empack/update-flow/README.md) already connects selection, optional materialization, two exports, and first recipient preparation. [Local signed inputs](empack/subscribed-flow/README.md) connect key setup, immutable staging, enrollment, offer persistence, failed then successful A-to-B installation, old-consumer ensure, and rollback. [Saved-offer consistency](empack/saved-offer/README.md) adds authored corrupt-state controls. Hosted channel production/transport, complete release production from current author state, graph/ownership faults, interruption, and real consumer launch remain separate.
- **npm, pnpm, and Yarn:** [workspace publication](js-workspace-publish/README.md) already joins selected publication, accepted prefixes, packed ranges, and isolated consumers for a generated graph. Arbitrary workspace/account authority, patch/version-decision release composition, and broad task/deployment closure remain open.
- **Mod Organizer 2 and Prism:** selected profile, routing, task, component, account, and content methods have scoped evidence. Complete supported-host installation/import/update through actual launch, output capture, and recovery remains open; a helper or offscreen Qt adapter is not that product flow.
- **Cargo:** [freshness](cargo/FRESHNESS.md), [configuration/run](cargo/RUN-CONFIG.md), and [binary installation](cargo-install/README.md) supply actual build, execution, retained-artifact, and partial ownership boundaries. Other sources/toolchains, cross-target execution, registry publication, concurrency, and interruption still need evidence.
- **restic:** [policy to restore](restic/POLICY-JOIN.md) already composes local selection, failed/successful deletion, pruning, checks, and exact restores. Remote/backend acceptance, concurrent owners, and interruption are not supplied by those local runs.
- **VS Code:** native edit/save, search/edit, task, provider lifetime, and [workspace enablement/runtime](vscode/ACTIVATION.md) joins now exist at different scopes. Trust/agent/task enforcement, profile switching, SCM/debug, remote/browser capabilities, and failure recovery still need their own policies and evidence.

These are not all-or-nothing acceptance matrices. Compose a bounded current rule and a discriminating failure case at each join, then record what the run actually exercised. A source-only method, simulated host, native component, and full product workflow remain different evidence categories.

## Work order after this audit

1. **Finish the missing author-transition contracts.** Assessment and migration now have honest source-map references, not new execution qualification. Trace observed-content adoption and explicit runtime migration through identity, current document/lock basis, policy retention, preparation, authorization, and actual publication. Reuse selection, synchronization, removal/re-adoption, Java, update-flow, and saved-state evidence. Inspect existing tests and the installed CLI before selecting one discriminating fixture. An update happy path, root re-promotion, or state-directory association cannot stand in for adopting observed bytes.
2. **Connect author state to remaining release/consumer obligations.** Reuse the completed snapshot and signed-input joins above. Identify the actual missing release-production, hosted delivery, old/new ownership, or runtime boundary before creating another publisher/recipient fixture. Preserve author intent, prepared inventory, signed metadata, retained bytes, installed ownership, and launch as different values.
3. **Continue comparator groups across their own inventories.** Review the application-specific gaps above, including unlinked reports, before new collection. Store/link/trust policy, account/registry authority, supported-host installation and launch, toolchain/source ownership, and backend concurrency are distinct groups. Do not reduce nine-application scope to convenient Mac or reporting-only features.
4. **Reconcile coherent targets as groups finish.** Use the now-linked candidate, preservation, and choice records to review current/proposed types, affected APIs and callers, ownership, compatibility, keep-current alternatives, and falsifying checks. Preserve the selected empack project-format clean break; comparator formats and native recovery authority have different obligations. No production migration framework is implied.

Before collecting another case, name the unanswered claim, its existing evidence, the discriminating observation, its host/profile and effect scope, and the decision it could change. Prefer a source comparison or retained-data replay when it answers that question. A new executable probe should add information, not reproduce a successful predicate or compensate for a missing inventory link.

The full study remains active. This audit changes the order of investigation and clarifies evidence reuse; it does not narrow the intent, approve a production design, or declare the pending operations complete.
