# Application study: remaining scope and evidence gaps

The nine-application study remains incomplete. Its strongest result so far is a set of attributable component decisions and counterexamples, with a bounded shared-engine portable-authoring join. The next work must connect missing application policies and workflows, and reconcile the target designs. More proof counts or repeated happy paths would not establish that result.

This is an interim review of the selected intent against the canonical [inventory](inventory.json), [scenarios](scenarios.json), [comparison](COMPARISON.md), per-program targets, and linked reports. The inspected baseline is `17363c3ffc7f1ed14d3e82a0df7f7f2d25f9a22a`, on 2026-11-26. The earlier `b8125d8` review remains in Git history; its counts and work order are historical. This review checks reference classification and target/workflow scope. It does not newly verify every model, source file, upstream version, or native capture. Operation and scenario states remain unchanged.

Another 554 have no inventory links. There are 139 families with operation-linked references and two with related-only components. These are reference counts, not completion or evidence-quality counts. An unlinked operation can have relevant material elsewhere; inspect the reports before collecting another fixture.

## Decision and target coverage

The indexes now contain 51 candidate records, 21 preservation records, and 17 unresolved choices. They name owning reports and compatibility obligations; they are not adopted changes or fresh upstream reviews. The query now shows proposal-only operation links separately and includes each scoped reference's recorded component status. Adding a proposal cannot become a new observed operation merely by adding a path.

Source-grounded structural/API targets are now available for every selected program: [empack authoring](empack/AUTHORING-API.md), [npm/pnpm/Yarn](js-architecture/README.md), [Cargo](cargo/ARCHITECTURE.md), [restic](restic/ARCHITECTURE.md), [MO2](mo2/ARCHITECTURE.md), [Prism](prism/ARCHITECTURE.md), and [VS Code](vscode/ARCHITECTURE.md). They connect current owners, policies, affected callers, formats, keep-current alternatives, and falsifying checks. Their bounded groups do not provide models and verified transitions for every operation.

The recent synthesis also recovered existing mechanisms and non-obvious compatibility constraints: retain VS Code's existing guarded reconciliation before another merger, preserve restic's scoped loaders and legacy codecs, propagate Cargo installation outcomes independently of tracking, and keep Prism component saving and stage publication distinct. MO2's callback comparison preserves future registrations separately from its delivered batch. None of these findings licenses a universal scheduler, transaction service, or cross-program migration framework.

The initial inventory is a research decomposition, not proof that each command exists with that spelling in every pinned release. Native help, selected sources, and plugin/version profiles must admit a feature before its behavior is claimed. Preserve unsupported or unavailable profiles explicitly; do not infer them from a blank evidence field.

## Reuse the joins already established

The [portable-authoring join](empack/PORTABLE-JOINED.md) already exercises a shared research engine through import, invalid and valid save/reopen, metadata/path edits, captured-image Prism export, and finalized browser downloads. It is not necessary to build another demonstration of that same sequence. Production project encoding, more providers and recipes, custody of signing material, storage limits, concurrent writers, crash behavior, and actual consumer launch remain separate obligations.

Earlier component reports describe what their own run did not establish. A later component can fill part of that gap without changing an earlier receipt or making its original observation broader. Current summaries should link the later evidence instead of presenting the earlier limitation as a newly missing experiment. Frozen producers, failures, and raw records remain unchanged.

Reuse later joins before treating earlier limitations as new missing experiments:

- **empack:** [Observed-content adoption](empack/adoption-flow/README.md) and [runtime migration](empack/migration-flow/README.md) already add released-CLI boundaries, including changed observed bytes, exact pins, explicit unpinning and refusals. [Author-to-snapshot](empack/update-flow/README.md) connects selection, materialization, two exports and first recipient preparation. [Local signed inputs](empack/subscribed-flow/README.md) connect native key setup/staging, enrollment, offers, installation, ensure and rollback; its channel documents are authored test inputs. [Saved-offer consistency](empack/saved-offer/README.md) adds corrupt-state controls. Native channel creation/advancement, hosted transport, graph/materialization faults, interruption and real consumer launch remain separate; do not repeat the completed migration pin pair as a missing experiment.
- **npm, pnpm, and Yarn:** [workspace publication](js-workspace-publish/README.md) already joins selected publication, accepted prefixes, packed ranges, and isolated consumers for a generated graph. Arbitrary workspace/account authority, patch/version-decision release composition, and broad task/deployment closure remain open.
- **Mod Organizer 2 and Prism:** selected profile, routing, task, component, account, and content methods have scoped evidence. Complete supported-host installation/import/update through actual launch, output capture, and recovery remains open; a helper or offscreen Qt adapter is not that product flow.
- **Cargo:** [freshness](cargo/FRESHNESS.md), [configuration/run](cargo/RUN-CONFIG.md), and [binary installation](cargo-install/README.md) supply actual build, execution, retained-artifact, and partial ownership boundaries. Other sources/toolchains, cross-target execution, registry publication, concurrency, and interruption still need evidence.
- **restic:** [policy to restore](restic/POLICY-JOIN.md) already composes local selection, failed/successful deletion, pruning, checks, and exact restores. Remote/backend acceptance, concurrent owners, and interruption are not supplied by those local runs.
- **VS Code:** native edit/save, search/edit, task, provider lifetime, and [workspace enablement/runtime](vscode/ACTIVATION.md) joins now exist at different scopes. Trust/agent/task enforcement, profile switching, SCM/debug, remote/browser capabilities, and failure recovery still need their own policies and evidence.

These are not all-or-nothing acceptance matrices. Compose a bounded current rule and a discriminating failure case at each join, then record what the run actually exercised. A source-only method, simulated host, native component, and full product workflow remain different evidence categories.

## Work order after this audit

1. **Bridge native release production to the existing subscriber join.** The missing boundary is channel creation and advancement by the released CLI, not another signature envelope authored by the fixture. Reuse retained exact payloads and existing key/stage/subscription evidence. Compare actual generated channel identity, release association, sequence, refusal and output bytes, then carry the result into the subscriber where useful. Channel creation itself verifies hosted immutable content, so first inspect its transport/trust requirements. Use an isolated local HTTPS fixture only with admitted certificate trust; do not disable verification or substitute another authored pointer. Public hosting and real consumer/game execution remain separate until actually exercised. Keep disposable private keys outside captures; no public deployment or personal channel mutation.
2. **Broaden missing domain models and joins.** Resolution/source/authority in package managers, actual store/link materialization, Cargo metadata-write/cleanup, restic concurrent/backend acceptance, editor trust/remote/agent features, and supported-host mod-management workflows require distinct evidence. A new source/field matrix should answer a named missing policy, not recheck a successful projection under another label. Retain exact unavailable-host obligations where this Mac cannot supply them.
3. **Exercise normal entry points where component reachability matters.** Prism's source methods and MO2's supported-host obligations need product-specific callers and real resource effects. Continue headlessly while the user needs the desktop. That constraint does not block source/models or isolated CLI work in other domains.
4. **Review the full empack proposal and compatibility plan.** The current 52 capability families, nine authoring contracts, native authority boundary, and research portable join are different scopes. Reconcile provider/network restrictions, project wire/asset retention, history/background/save/export, release/trust/instance ownership, API errors and native adapters against all remaining requirements. Review the whole target with the host owner before production adoption. Preserve the selected project-format clean break; comparator saved formats and legacy native recovery have separate obligations.

Before collecting another case, name the unanswered claim, its existing evidence, the discriminating observation, its host/profile and effect scope, and the decision it could change. Prefer a source comparison or retained-data replay when it answers that question. A new executable probe should add information, not reproduce a successful predicate or compensate for a missing inventory link.

The full study remains active. This audit changes the order of investigation and clarifies evidence reuse; it does not narrow the intent, approve a production design, or declare the pending operations complete.
