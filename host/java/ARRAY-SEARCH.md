# Matching values are not a stable duplicate index

The selected Java SE [17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Arrays.html#binarySearch(float%5B%5D,float)), [21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Arrays.html#binarySearch(float%5B%5D,float)), and [25](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Arrays.html#binarySearch(float%5B%5D,float)) contracts require a sorted input for `Arrays.binarySearch(float[],float)`. A match may return any matching duplicate. An absent key returns a negative encoding of its insertion point. An unsorted input is outside that contract; it is not a promised runtime refusal.

[Lean](ArraySearch.lean) and [Bend](ArraySearch.bend) model an ordered integer-valued float subset. They separate the API-permitted matching/insertion result from a stronger last-at-or-below policy. The [authored cases](array-search-cases.json) admit first, middle, and last matching duplicates. These are documentation-derived permissions, not three additional JVM observations. The adapter excludes NaN, infinities, arbitrary fractions, and signed-zero distinctions; this is not a complete floating-point model.

The actual consumer is [Minecraft 1.21.4 range dispatch](../minecraft/JAVA-1.21.4.md). Its original private index helper uses a linear last-at-or-below loop for fewer than 16 entries and the library binary search from 16 onward. On the recorded Temurin 21/macOS profile, 15 equal thresholds select index 14; 16 equal thresholds select index 7. Both choices satisfy their respective contracts. The model deliberately also admits other matching indices in the binary branch. A later JDK implementation can make a different permitted choice without violating this API contract.

For this consumer, the captured index has already been converted from the library's result to a model/fallback index. The comparison checks this composed contract; it does not reconstruct an unobserved raw library return or predict a universal midpoint algorithm. Java 17 and 25 are documented API reference profiles here, not new native array-search runs. The game itself declares Java 21, and its Java 21 class files are not qualified for execution on 17.

These contracts do not promise that a mutable input remains sorted while another writer changes it. The fixture supplies one private array and records its numeric before/after images. Concurrent mutation, shared-memory publication, other array types/overloads, and native behavior on other OS/JDK builds remain outside this band.

A caller that needs one stable duplicate winner must supply its own policy or reject ambiguity under an explicit authoring rule. Silently deduplicating thresholds, reordering equal entries, or asserting the last entry always wins can change visible behavior. Keeping the existing selection is a valid alternative. No runtime implementation or asset conversion is selected here.
