# Long arithmetic and mutable buffer metadata

Java integer multiplication keeps the low bits on overflow. A later narrowing round trip therefore establishes representability of the wrapped result, not the original mathematical product. `Math.multiplyExact` instead throws on overflow. These are separate contracts in [JLS 17 §15.17.1](https://docs.oracle.com/javase/specs/jls/se17/html/jls-15.html#jls-15.17.1) and the [Java 17 Math API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Math.html#multiplyExact(long,long)); the selected [Java 25 language contract](https://docs.oracle.com/javase/specs/jls/se25/html/jls-15.html#jls-15.17.1) preserves the multiplication rule.

[Word64.lean](Word64.lean) and [Word64.bend](Word64.bend) distinguish signed-int widening, long word bits, narrowing/sign extension, and an unbounded positive-input checked-product predicate. Bend uses bounded word operations and 16-bit limbs; no large word is converted to unary `Nat`. The checked-product helper's inputs are positive signed-int dimensions admitted by the research codec. It is not a general implementation of every `Math` overload.

The consuming [Minecraft header comparison](../minecraft/IMAGE-HEADERS.md) retains twelve authored arithmetic observations on actual macOS/aarch64 Java 17.0.21.1, 21.0.13.1, and 25.0.4.1. Both negative and positive wrapped values can pass the narrowing test while checked multiplication throws. This qualifies those bounded cases on the three recorded runtimes, not other hosts or every arithmetic input. The Lean and Bend rules are independent models, not a JVM translation proof.

The [Java 17 Buffer API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/nio/Buffer.html) separates absolute reads from position and read-only content from mutable metadata. [ByteBuffer.order](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/nio/ByteBuffer.html#order(java.nio.ByteOrder)) changes interpretation of multibyte values. A read-only view or a function named validation does not establish unchanged order, unchanged other metadata, or thread safety. The consumer fixture observes order effects on failure, unchanged content/position/limit, and absolute-index admission despite only one remaining byte. That buffer witness runs on Java 21/25; Java 17 buffer execution remains unqualified here.

Before a native allocation, preserve the original dimensions, checked product, requested representation, policy budget, actual allocation result, and owner lifetime separately. Source estimates are not measured physical memory. Neither header admission nor CPU image closure establishes upload success or device retirement. Windows/Win32, macOS/Darwin, GNU/Linux, alternate JVMs, direct/mapped buffers, and native image libraries retain their own profile and ownership premises.
