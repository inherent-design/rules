# Selected float order and signed zero

The Java SE [17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Float.html#compare(float,float)), [21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Float.html#compare(float,float)), and [25](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Float.html#compare(float,float)) APIs give `Float.compare` the same ordering sign as `compareTo`. That order distinguishes negative and positive zero and places the NaN class after ordinary values. Primitive numeric comparisons treat the zeros as equal and return false when an operand is NaN. These are different operations with different contracts.

[FloatOrder.lean](FloatOrder.lean) and [FloatOrder.bend](FloatOrder.bend) represent the exact selected values minus ten, negative zero, positive zero, plus ten, and one NaN class. They separate total ordering, numeric comparison, key identity, NaN detection, and multiplication by the selected exact scales plus or minus one. Fifteen Lean laws and eight Bend laws preserve the distinction. The model does not encode arbitrary float bits, fractions, infinities, overflow, underflow, rounding, NaN payloads, or a general arithmetic implementation.

The scale operation also follows the [Java language multiplication rules](https://docs.oracle.com/javase/specs/jls/se25/html/jls-15.html#jls-15.17.1) for this subset. Scaling a zero by minus one reverses its sign; a NaN stays in the modeled NaN class. No claim is made about a particular NaN bit pattern or general arithmetic on excluded values.

The consumer is the in-progress [item-program study](../minecraft/ITEM-PROGRAMS.md). The delivered Compat generic compiler uses float-key equality when checking duplicate thresholds and `Float.compare` during dispatch. Its captured signed-zero definition produces different layers for negative and positive zero. Its authored numeric callback also supplies NaN, which takes the fallback. The selected Modefite resolver instead combines a descending float comparator with primitive `>=`; a shared sort key does not make those selection policies identical.

These original generic-compiler calls ran on the pinned Java 21/macOS profile with explicit authored callbacks. They do not establish all numeric values of real game properties, a direct 25-pair JVM comparison, Java 17 or 25 native qualification, Windows/Linux behavior, or full renderer parity. The host baseline remains Java 17 with 21/25 overlays; source/API reference coverage and actual native coverage retain separate states.

The existing [array-search model](ARRAY-SEARCH.md) keeps its integer-valued subset and signed-zero/NaN exclusions. This module supplies a separate selected contract for consumers that need those distinctions. A converter or proposed provider must name its equality and ordering policy before deduplicating, sorting, or selecting thresholds. These rules authorize no implementation change or automatic runtime upgrade.
