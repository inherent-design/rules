# Provider capabilities and composition

The selected Modefite, Polytone, and Compat artifacts supply different resource languages and consumers. They are not interchangeable releases of one graphics API. The [contract map](provider-contracts.json) adds eight scoped capability records against the canonical 52-family inventory and all eight selected provider variants. The [source ledger](provider-sources.json) binds 176 original class identities and 113 private inspection views. This is a partial comparison, not completed provider coverage or a deployment recommendation.

The selected deployment reference remains Java Edition 1.21.1 with NeoForge 21.1.265. The five vanilla release references, separate Bedrock lane, and [28 Polytone manager domains](POLYTONE.md) remain independent research targets. No provider, game, or pack was installed or launched for this band.

## Eligibility, selection, and use

Keep these facts separate in a capability receipt:

1. Requested capability and its edition/release/provider identity.
2. Supplied or observed dependency metadata, effective libraries, settings, and physical side.
3. Policy result and candidate hook names.
4. Actual applied transformations and ordering.
5. Definition admission, context/reference availability, and selected consumer output.
6. Bake/publication, renderer/backend behavior, and retirement obligations.

The isolated native fixture executes 55 original `FeatureSelection.select` calls. Forty-nine return and six throw. Four additional variant rows deliberately skip that call because Compat is not selected; those rows are authored procedure evidence. Polytone metadata alone does not satisfy the Modefite dependency. When the settings are enabled and the client-side guard holds, the selected wrong version throws before a `FeatureSelection` value is returned. Disabled or wrong-side branches do not require a successful version check.

Both selected defaults are true. Five original `FeatureSettings.read(StringReader)` cases retain default behavior, valid explicit values, duplicate rejection, uppercase-value rejection, and unknown-key rejection. Those five calls are observations, not a formal properties parser model. `load(Path)`, configuration creation/migration, real FML metadata, actual dependency negotiation, and plugin execution were not called. The plugin's inspected `shouldApplyMixin` returns true; its candidate selection occurs through `getMixins`. Treating the former Boolean as the startup gate would be wrong.

The [policy model](ProviderPolicy.lean), [Bend decisions](ProviderPolicy.bend), and [comparison](evidence/provider-policy-conformance.json) match the 55 original calls and four skipped procedure rows. Fourteen Lean and eight Bend laws retain disabled, wrong-side, missing, eligible, and rejected outcomes separately. Thirteen research-decoder refusals, three unneeded-unknown examples, and six changed observations check the selected projection. Presence is supplied to this fixture, not measured from an installed client.

## Restricted geometry conversion

The original Compat helper returns its input unchanged unless it is an object with an element array, lacks `loader`, `parent`, and `transform`, and contains an Euler element. Its Euler predicate requires x/y/z presence and absence of both axis and angle. A hybrid rotation is therefore unchanged by this helper, while Polytone's inspected x/y/z branch recognizes it. Unchanged does not mean validated, supported, or accepted downstream.

Only after finding an Euler element does the helper enforce its 128-element limit and inspect the conversion bodies. Consequently, an oversized legacy array or malformed sibling can pass through unchanged when no Euler element is detected. In the conversion branch, non-object siblings, non-Boolean rescale, true rescale, cull-face presence, bad origin shape, and nonfinite/non-numeric values have distinct refusal points. Error order is part of the scoped contract; it is not a generic safe-parser claim.

For selected successful inputs, root fields are retained except `elements` and `groups`; the helper supplies a composite loader and children. Each rotating child copies four selected root fields and one element body without its rotation. Legacy bodies form a separate child. These checks retain the root/child distinction rather than counting matching element totals as preservation.

The [adaptation model](ProviderAdaptation.lean), [Bend model](ProviderAdaptation.bend), and [comparison](evidence/provider-adaptation-conformance.json) match 27 original helper calls: 25 initial cases and two mixed-axis supplements. Fourteen Lean and eight Bend laws cover the selected structural decisions. Fifteen research-decoder refusals, three unneeded-unknown examples, and five altered-output controls pass. Eight emitted matrices match 40 independently calculated double-precision point transforms, including pivot and rotation-order controls, at absolute tolerance `2e-6`.

Those numerical checks cover finite selected angles within 360 degrees and origin coordinates within 64 model units. They do not prove the matrix implementation, normals, UVs, rescale, culling, winding, lighting, NeoForge composite-loader interpretation, or pixel equivalence. The constructed nonfinite-matrix branch remains source-only. The frozen `inputBytesUnchanged` field means Gson serialization before and after the helper is equal; it does not compare raw request-file bytes or exclude intervening mutation. The default Gson serializer omits the selected null result's `output` member, while retaining its observed same-object flag.

## Coexistence and ownership

Two similar scalar-angle hook declarations establish an overlap to investigate. They do not prove a conflict, safe composition, or a particular callback winner. Polytone's Euler path and Compat's outer JSON conversion also operate at different stages. If an applied Compat hook rewrites the selected input before the element decoder, that resulting element no longer carries its Euler rotation; that conditional source relationship is not an observed transformed pipeline.

Qualifying a combination requires the exact effective provider/library set, settings, applied hook order, resource stack, input grammar, context, and actual consumer. Include parented models, custom loaders, hybrid rotations, cull faces, rescale, generated geometry, legacy overrides, and custom item renderers. Preserve the owner of each mutation and fallback. Decode success cannot establish culling or renderer correctness, and reload completion cannot establish physical resource retirement.

The inspected Polytone hook constructs its Euler rotation with rescale false and changes a winding condition. That differs from Compat's explicit refusal of true rescale and cull-face fields. Neither behavior supplies a proof of faithful 1.21.11 geometry on 1.21.1. Existing source searches found no `shade_direction_override` implementation in the selected provider roots; this scoped absence is not a universal claim about future providers or all external integrations. The selected 26.3 shading contracts remain a separate comparison target.

## Selectable design directions

The map preserves four independent options: retain the current choices; extend a named provider; convert a closed asset subset; or design a combined provider. None is selected for implementation or rollout.

A proposed combined provider should name each capability, source grammar, original consumer, required game/context state, owned hook, fallback, and reload/retirement boundary. Report eligible, inactive, rejected, unresolved, and applied states separately. Preserve the original definition and useful diagnostics when conversion refuses. A converted asset needs a declared supported subset and semantic-loss account; changing syntax does not create an older host's absent item, component, action, registry datum, or special renderer.

Before removing either provider, compare its relevant domains individually, including Polytone's other managers and Modefite's actual item consumers. A new mod's common capability receipt can be versioned independently of its resource grammars and host adapters. Do not use one global release label as proof of every feature or automatically request an upgrade. Version negotiation, optional dependencies, restart/reload needs, and safe refusal need named contracts before implementation.

## Evidence and checks

The two exported captures preserve authored requests, producers, original outcomes, raw command channels, and normalized provenance. Original JARs, classes, private views, exact class paths, and class-load logs remain owner-local. The original fixture uses the delivered Compat artifact, Temurin 21.0.13.1+2-LTS on macOS arm64, Gson 2.10.1, JOML 1.10.5, and an explicit Maven artifact test dependency. No Minecraft or NeoForge class was loaded. The latter dependency does not qualify actual FML or JarJar selection.

There were 87 selected primary original entrypoint calls: 55 selection, five Reader, and 27 adaptation calls. Setup and getters are not included in that count. One compiler and two JVM groups completed and were checked absent. JVM limits and group retirement do not measure physical RAM reclamation or incidental library effects. Formal-code constructor/reserved-identifier fixes and a replay's initial null-output assumption were research harness corrections; native observations were not rewritten or recollected.

```sh
python3 host/minecraft/provider_policy_conformance.py
python3 host/minecraft/provider_adaptation_conformance.py
python3 host/minecraft/provider_contracts_check.py
```

It starts no JVM. Whole-provider feature semantics, actual transformed pipelines, full startup, pack/reload/render behavior, native Windows/Linux qualification, and the broader completion audit remain open.
